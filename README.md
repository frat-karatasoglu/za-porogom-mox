# За порогом — бюро переселения привидений

Рабочая панель оператора бюро, которое переселяет привидений из старых домов в новые места
обитания. Приложение подбирает каждому привидению место, объясняет решение простым языком,
показывает, кого переселить нельзя и почему, и позволяет оператору принять другое решение
вручную — но не молча.

Тема сказочная, задача практическая: понятная модель данных, объяснимый алгоритм,
обработанные краевые состояния и честный AI Worklog прямо внутри интерфейса.

- **Рабочая ссылка:** публикуется через GitHub Pages, см. раздел [Публикация](#публикация).
- **Репозиторий:** https://github.com/frat-karatasoglu/mox-ghost-relocation-ai
- **AI Worklog:** вкладка «AI Worklog» внутри самого приложения.

## Что можно сделать за первую минуту

1. Нажать **«Подобрать места»** — бюро расселит очередь и объяснит каждое решение.
2. Открыть карточку любого дела — справа появится разбор: условия переселения, причина
   отказа и список всех проверенных мест с конкретной причиной по каждому.
3. Выбрать другое место в блоке **«Переселить вручную»** — если оно не подходит, приложение
   назовёт нарушенное условие и не применит решение без отдельного подтверждения.
4. Перейти на вкладку **«Отчёт»** — сводка, самые проблемные заявки и загрузка мест.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:5173`.

| Команда | Что делает |

## Стек и границы

React 19 + TypeScript + Vite, тесты на Vitest. Бэкенда, авторизации и обращений к внешним
API нет: состояние живёт в `localStorage` браузера и переживает перезагрузку страницы.
Секретов и токенов в коде нет и быть не может — приложение никуда не ходит по сети.

```
src/
  domain/      модель данных, правила подбора, отчёт — чистые функции без React
  state/       хранилище (localStorage) и связывающий хук
  ui/          интерфейс: вкладки, карточки дел, панель дела
  content/     текст AI Worklog, вынесенный из разметки
```

Логика подбора намеренно отделена от интерфейса: файлы `src/domain/*` ничего не знают
о React, поэтому их можно проверять тестами без браузера, а интерфейс строит объяснения
из тех же функций, которые принимают решение.

## Модель данных

**Заявка** — имя, номер дела, род имени (для подписей «Расселён / Расселена / Расселено»),
уровень тревожности 1–10, любимая температура, крайний срок переселения и блок
структурированных особых условий:

| Поле | Смысл |
| --- | --- |
| `noTickingClocks` | Не переносит тикающих часов |
| `noBells` | Не переносит колоколов |
| `needsDraught` | Нужен сквозняк |
| `avoidsHumans` | Нельзя селить рядом с людьми |
| `needsAttic` | Нужен чердак |
| `fearsMirrors` | Боится зеркал |
| `maxLight` | Максимально допустимая освещённость 0–10 (или без ограничения) |
| `maxNoise` | Максимально допустимый уровень шума 0–10 (или без ограничения) |
| `forbiddenTypes` | Типы мест, в которые селить нельзя |
| `lovesDamp` | Любит сырость — **предпочтение**, а не запрет |

**Место** — название, тип, вместимость, температура, освещённость, шум, влажность, наличие
людей, чердака, зеркал, тикающих часов, колоколов и сквозняка, плюс собственные ограничения:
предел тревожности жильцов и признак «закрыто на приём».

У заявки и у места есть поле `note` со свободным текстом. **Алгоритм его не читает** — оно
существует только для людей. Всё, на чём строится решение, лежит в структурированных полях.

### Занятость мест не хранится

Ключевое решение модели: число жильцов нигде не сохраняется, оно всегда вычисляется из
списка размещений (`computeOccupancy`). Из этого бесплатно следуют три нужных свойства:

- повторный автоподбор не удваивает счётчики;
- ручной перенос сразу освобождает прежнее место;
- если жильцов оказалось больше вместимости, это видно при первом же пересчёте, и отчёт
  показывает превышение вместо тихого расхождения цифр.

## Правила подбора

Подбор идёт в два шага: сначала жёсткий фильтр, затем баллы.

### Шаг 1. Жёсткие условия

Место, не прошедшее хотя бы одну проверку, исключается целиком — баллы уже не важны.

| Проверка | Место не подходит, если |
| --- | --- |
| Свободные места | все места заняты |
| Приём заявок | место закрыто на приём |
| Чердак | нужен чердак, а его нет |
| Зеркала | заявка боится зеркал, а зеркала есть |
| Соседство с людьми | селить рядом с людьми нельзя, а люди есть |
| Тикающие часы | заявка их не переносит, а часы тикают |
| Колокола | заявка их не переносит, а колокола есть |
| Сквозняк | сквозняк обязателен, а его нет |
| Освещённость | света больше, чем допускает заявка |
| Уровень шума | шума больше, чем допускает заявка |
| Тип места | тип указан в заявке как неприемлемый |
| Предел тревожности места | тревожность выше предела, принятого местом |

В интерфейсе показываются только применимые правила: если привидение не боится зеркал,
строки про зеркала в разборе не будет.

### Шаг 2. Баллы совместимости (0–100)

Прошедшие фильтр места сравниваются по четырём мягким критериям. Каждый даёт «соответствие»
от 0 до 1, веса нормируются так, чтобы в сумме получалось 100 баллов.

| Критерий | Как считается | Вес |
| --- | --- | --- |
| Температура | `1 − разница_температур / 15`, разница обрезается по 15 °C | 35 |
| Влажность | любит сырость → `влажность / 100`; иначе комфортом считается 50 % | 20 |
| Тишина | `1 − шум / 10` | 15 + 20 × (тревожность / 10) |
| Темнота | `1 − свет / 10` | 10 + 15 × (тревожность / 10) |

**Как влияет тревожность.** Она не запрещает ничего, но меняет приоритеты: чем тревожнее
привидение, тем больший вес получают тишина и темнота и тем меньший — температура. Для
спокойного жильца решает температура, для крайне тревожного — тишина и отсутствие света.

При равенстве баллов порядок детерминирован: сначала место с бо́льшим числом свободных мест
(расселение равномернее), затем по алфавиту. Одинаковые входные данные всегда дают
одинаковый результат.

### Очерёдность заявок и роль дедлайна

Заявки обрабатываются по возрастанию остатка дней до срока: просроченные имеют
отрицательный остаток и потому идут первыми. При равном сроке вперёд проходит более
тревожное привидение, при полном равенстве — по алфавиту.

**Просроченный срок не является причиной отказа.** Отказать в переселении из-за того, что
заявку слишком долго не рассматривали, было бы наказанием жильца за работу бюро. Поэтому
просроченная заявка получает наивысший приоритет, помечается в списке и отдельно считается
в отчёте — но место ей ищут по тем же правилам, что и всем.

### Честно об алгоритме

Подбор жадный и последовательный: каждая заявка получает лучшее доступное место на своём
шаге. **Он не гарантирует оптимального суммарного результата** — заявка с ранним сроком
может занять место, которое сильнее подошло бы следующей. Это осознанный размен: решение
остаётся объяснимым оператору построчно, а исправить частный случай можно вручную.

## Ручные изменения

Правило одно и действует везде: **бюро ничего не запрещает, но не делает молча.**

- Подходящее место — кнопка «Подтвердить переселение» активна, размещение применяется сразу.
- Неподходящее место — основная кнопка остаётся неактивной, появляется красная строка
  с названием нарушенного условия и **отдельная** кнопка «Разместить вопреки условиям».
  Согласие и отказ — разные действия, случайно нажать не получится.
- Принятое вопреки условиям размещение помечается флагом в данных, бейджем в карточке и
  отдельным счётчиком в отчёте.
- Ручные размещения переживают повторный автоподбор: пересчитываются только автоматические.
- Редактирование заявки снимает её текущее размещение: условия изменились, и прежнее решение
  могло стать неверным.

## Обязательные состояния

Все они воспроизводятся на демо-данных без подготовки:

| Состояние | Где увидеть |
| --- | --- |
| Пустой список заявок | удалить все дела — появится объяснение и кнопка возврата демо-данных |
| Нет подходящего места | дело П-043 «Шёпот в Ленте»: колокола и требование тишины закрывают всё |
| Подходящее место занято | дело П-041 «Шорох Почтовый»: единственную подходящую башню занимают раньше по очереди |
| Просроченная заявка | дело П-042 «Пыльный Архивариус» |
| Место закрыто на приём | «Часовня у брода» — условия подходят, но приём закрыт |
| Конфликт при ручном выборе | выбрать «Пустой вокзал» для дела П-041 |
| Превышение вместимости | разместить вопреки условиям в заполненное место — отчёт покажет перегрузку |
| Повреждённые данные | испортить ключ `mox-ghost-bureau/v2` в DevTools и перезагрузить страницу |

### Ручные сценарии

Полный чеклист с ожидаемыми результатами лежит внутри приложения, на вкладке
**«AI Worklog» → «Чеклист самопроверки»**, чтобы проверяющему не нужно было держать README
рядом. Коротко:

1. **До подбора.** Открыть дело, которому место ещё не искали. Ожидание: статус «Ожидает
   места» и число подходящих мест, а не отказ.
2. **Автоподбор.** Нажать «Подобрать места». Ожидание: расселены 5 из 8, полоса показателей
   сама пересчитывается на 3 без места, 4 свободных места, 1 просрочена.
3. **Нет места.** Дело П-043. Ожидание: по каждому месту названо нарушенное условие.
4. **Место занято.** Дело П-041. Ожидание: «Башня без стрелок» помечена «Занято 1/1»
   с подписью «Все условия соблюдены» — причина в занятости, а не в конфликте.
5. **Конфликтный ручной выбор.** Для дела П-041 выбрать «Пустой вокзал». Ожидание: основная
   кнопка неактивна, названо нарушенное условие, согласие требует отдельной кнопки; после
   него заявка помечена «Вопреки условиям» и попала в отчёт.
6. **Сохранение.** Перезагрузить страницу. Ожидание: все решения на месте.
7. **Узкий экран.** Сузить окно до ширины телефона. Ожидание: карточки в одну колонку, панель
   дела открывается поверх списка и закрывается крестиком или нажатием на фон.

## Известные ограничения

- Подбор жадный и не оптимален по суммарному баллу (см. выше).
- Места переселения редактируются только в коде: в интерфейсе можно менять заявки, но не места.
- Нет журнала действий и отмены последнего решения.
- Веса мягких критериев зашиты в код и не настраиваются из интерфейса.
- Состояние хранится в `localStorage`: оно не общее для нескольких операторов и живёт
  в одном браузере.
- Тестами покрыта логика подбора и хранение; тестов на сами React-компоненты нет, интерфейс
  проверялся вручную по чеклисту выше.

## Публикация

В репозитории лежит workflow `.github/workflows/deploy.yml`, который на каждый push в `main`
прогоняет тесты, собирает проект и публикует его на GitHub Pages.

Чтобы ссылка заработала, нужно один раз включить Pages в настройках репозитория:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. Дождаться завершения workflow во вкладке **Actions**.
3. Адрес появится там же и будет иметь вид
   `https://frat-karatasoglu.github.io/mox-ghost-relocation-ai/`.

Сборка использует относительные пути (`base: './'`), поэтому одинаково работает и в корне
домена, и в подкаталоге — при желании `dist/` можно просто выложить на любой статический
хостинг.

## AI Worklog

Журнал работы с AI встроен в приложение отдельной вкладкой: инструменты, этапы с разделением
«что делал человек / что делал AI», ключевые запросы, решения человека и решения AI
раздельными списками, реальные ошибки AI, планы доработок и чеклист самопроверки.

Поля, которые ещё не измерены или относятся к зоне ответственности автора работы (общее время
и расход токенов), помечены значком «нужно уточнить» и не заполнены выдуманными числами.
